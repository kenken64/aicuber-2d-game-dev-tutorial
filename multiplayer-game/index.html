      HOW THE NETWORK ROOM WORKS

      One room, two live connections.

      Each player view opens its own WebSocket. The server assigns the room code, relays chat and readiness, and starts the round after both players are ready.

      The server owns movement and coin scores, then sends the same game state to both views. If a player leaves, the room returns to the lobby.

      Forest, explorer and coin art reused from the earlier Godot Forge game modules.

      BUILD PROMPTS

      Prompts for the networked room

      Open a card to read the exact build prompt. It stays on this page, alongside the working example.

      WebSocket lobby and chat prompt
      Build a two-player browser game lobby using WebSockets on the same HTTP server. Either Player 1 or Player 2 may host a room and receive a short join code; the other joins with that code. Show both player views on one page, while also allowing a second browser to join. Keep separate WebSocket connections for each player view. Broadcast room membership, player names, chat messages and ready state to both clients. Start the game automatically only when both players have joined and marked ready. Validate room codes and messages, cap rooms at two players, and return to the lobby if either player leaves.
      Synchronized game-state prompt
      Create a short shared-screen forest coin game for two networked players. Player 1 uses A/D and W; Player 2 uses the arrow keys. Clients send only input state over WebSockets. The server advances player positions, jumping, coin ownership and scores on a fixed tick, then broadcasts the same authoritative state to both game views. Draw both explorers and every remaining coin in each view, highlight the locally controlled player, and display the two scores. End the round when all coins are collected, then allow both players to ready up for another round. Handle disconnects without leaving a stale active match.
